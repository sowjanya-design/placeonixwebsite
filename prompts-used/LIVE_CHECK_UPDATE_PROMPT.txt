REAL BUG FOUND — nav is broken specifically on the HOMEPAGE
=====================================================================
On the homepage (index.html) at full desktop width (1568px tested), the nav
does NOT show the horizontal menu bar with dropdowns — it shows ONLY the
hamburger icon, and clicking it opens the mobile slide-out drawer (correctly
containing the new SAP Courses / Technology Courses / Combo Programs
accordion groups) even though the viewport is far wider than the site's own
~768px mobile breakpoint.

ROOT CAUSE (confirmed structurally, verify in code): public/index.html has
its OWN separate inline <style> block, independent from
public/assets/css/site.css. The nav-restructure and nav-responsive fixes were
applied correctly to site.css (proven by course pages rendering correctly),
but index.html's inline stylesheet still has the OLD nav CSS — most likely
missing the `@media (max-width: 768px)` scoping on the rule that shows
`.nav-toggle` / hides `.nav-menu`, so that rule is applying unconditionally
at all widths on the homepage only.

FIX:
1. Open index.html's inline <style> block and find its nav-toggle/nav-menu
   rules. Compare them directly against the corrected version in
   public/assets/css/site.css (the .nav-toggle { display: none } default,
   with the mobile override scoped inside @media (max-width: 768px)).
2. Bring index.html's inline nav CSS in line with site.css's — either by
   fixing the media-query scoping directly in index.html's <style> block, or
   (better, if feasible without a big refactor) having index.html simply link
   to the shared site.css for nav-related rules instead of maintaining a
   duplicate copy, to prevent this exact class of drift happening again.
3. Verify: at 1440px+ width, the homepage must show the full horizontal nav
   bar with all three category dropdowns working on hover — same as the
   course pages already do. At <768px, it should still collapse to the
   hamburger drawer as intended.
4. While in there: grep both stylesheets for any OTHER rule that exists in
   one but not the other (nav, buttons, badges, footer) and flag anything
   else that's drifted, since this is exactly how homepage/course-page visual
   inconsistencies happen — the two-stylesheet setup is fragile.
