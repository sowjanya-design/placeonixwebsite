PART 2 — TIMED APPEARANCE (clarifying the request before building it)
=====================================================================
The request was "make this form appear every 30 seconds when anyone opens the
website." Read literally, a popup that RE-INTERRUPTS every 30 seconds while
someone is reading the site is aggressive and drives visitors away — that is
almost certainly not the intent, and it's not the pattern ExcelR itself
actually uses (their own popup appears once, after a delay, not on a repeating
timer). Build it the way that actually converts, and treat the "30 seconds"
as the ONE-TIME delay before it first appears:

1. Show the popup ONCE, 30 seconds after a visitor lands on the homepage (or
   any page, your call — homepage is the highest-traffic entry point, so
   starting there is reasonable).
2. Use sessionStorage (not localStorage) to make sure it does not show again
   on later page navigations within the same visit, and does not reappear if
   the visitor already submitted the form or explicitly closed it.
3. Do NOT make it repeat every 30 seconds indefinitely — that pattern
   measurably increases bounce rate and would actively hurt conversion, the
   opposite of the goal. If you genuinely want re-prompting behavior later,
   the sane version is "show again on a future NEW session after some days
   have passed," not "every 30 seconds in the same visit" — flag this to me
   explicitly if you think the literal every-30-seconds behavior is still
   wanted after reading this, rather than silently building the aggressive
   version.
4. Respect prefers-reduced-motion for the modal's open/close transition.

PART 3 — CURRICULUM ACCORDION: ONLY ONE WEEK/MODULE OPEN AT A TIME
=====================================================================
Currently, each course page's curriculum section uses native <details class="mod">
elements (see the #curriculum section in any course page, e.g.
public/courses/sap/sap-btp.html) — by default, native <details> elements are
all independent, so multiple weeks/modules can stay open simultaneously.
Fix: opening a new week/module should automatically close whichever one was
previously open, so only one is expanded at a time.

1. Preferred fix (simplest, no JS): give every <details class="mod"> element
   within the same curriculum block a shared `name` attribute, e.g.
   `<details class="mod" name="curriculum-sap-btp">`. Modern browsers (current
   Chrome, Edge, Safari 17+, Firefox 129+) natively treat same-`name`
   <details> elements as an exclusive accordion group — opening one closes
   the others, with zero JavaScript.
2. Add a small vanilla-JS fallback (a shared function, included once in the
   site's common script, not duplicated per page) for older browsers that
   don't support the `name` grouping: on a `toggle` event, if a details
   element was just opened, find its siblings with the same accordion
   container/class and close (`.open = false`) any others that are open.
3. Apply this to EVERY course/combo page's curriculum accordion — this is a
   shared pattern, so fix it once in a way that applies everywhere (a shared
   snippet/partial or a global script hook), not per-page copy-paste.
4. Verify: on any course page, open Module/Week 1, then click Module/Week 3 —
   Module 1 should auto-collapse. Keyboard operation (Tab + Enter/Space on
   the summary) must also trigger the same auto-close behavior, not just
   mouse clicks.
