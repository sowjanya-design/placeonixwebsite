ISSUE 2 (MEDIUM — mobile layout) — World-map background in the Trust
Stats band looks wrong/heavy at mobile width
=====================================================================
CONFIRMED: web-next/src/app/home.css, `.trust-stats` (~line 1094) and
`.trust-stats::before` (~line 1105-1116) apply ONE shared world-map
mask-image (`/assets/img/world-dots-white.png`, mask-size: contain)
positioned absolutely (inset: -50px) behind the whole 3-column stat
grid. At desktop width this is one elegant shared map behind all 3
numbers side by side.

At the mobile breakpoint (`@media (max-width: 640px)`, ~line 1188),
`.trust-stats` switches to `grid-template-columns: 1fr` (stats stack
vertically), but `.trust-stats::before` isn't given a corresponding
mobile-specific rule. On the live mobile render, this results in the
world map appearing to repeat/loom large behind EACH stacked stat
number individually rather than reading as one cohesive band graphic
— it looks heavy, oversized, and disconnected from the numbers rather
than a subtle background texture (confirmed via live screenshot: the
map graphic dominates visually between "2,000+ Learners" and "150+
Corporate Clients", taking up far more vertical space than the text
content itself).

FIX: add a mobile-specific override for `.trust-stats::before` inside
the existing `@media (max-width: 640px)` block (or a new one) that
either (a) sets a fixed, smaller mask-size (e.g. `mask-size: 140%` or
similar tuned value — test visually) so the map reads as a subtle
background texture rather than a dominant graphic at narrow widths, or
(b) reduces `opacity` further on mobile (currently 0.15 on desktop —
confirm whether it needs to go lower when the same map is stretched
over a much taller, narrower box), or (c) simplifies to a much lower
`inset` value so it doesn't bleed dramatically wider than the content.
Test at 375px and 414px and pick whichever reads as "clean and
premium," not "a giant world map crammed between numbers."

ISSUE 3 (MEDIUM — recurring, not new) — Scroll-reveal blank/white
flash is STILL happening, confirmed on this pass too
=====================================================================
This was already flagged in an earlier audit (LIVE_CHECK_UPDATE
history) and is STILL reproducible: scrolling down the homepage at
mobile width produces a fully blank white screenshot momentarily
between sections, even with a full 1-second pause inserted before
capturing — meaning it isn't purely a "scrolled too fast" artifact,
it's a real, repeatable rendering gap tied to the `.reveal` /
IntersectionObserver fade-in pattern re-triggering or mistiming on
every section transition, not just an occasional edge case.

FIX (if not already fully applied — this needs to actually be
re-verified, not assumed fixed from a prior pass): find the shared
reveal/IntersectionObserver logic (check
web-next/src/components/layout/RevealObserver.tsx) and:
1. Confirm the initial CSS state for `.reveal` elements is NOT
   `opacity: 0` with a long trigger distance — shorten the trigger
   rootMargin so content becomes visible well before it's fully
   scrolled into view, not exactly as it enters the viewport.
2. Confirm `prefers-reduced-motion` fully disables this animation
   (immediate full-opacity render) — test with that OS setting on.
3. Test specifically at mobile scroll speeds (flick-scroll on an
   actual touch device or Chrome's touch-emulation mode, not just
   mouse-wheel scroll in desktop devtools) since mobile momentum
   scrolling moves through sections much faster than a
   mouse-wheel/trackpad scroll.
